A model at 92% accuracy does not remove 92% of the work.

If you cannot tell which 8% are wrong, you review all of it. You have added a system on top of the humans and removed almost nothing. That is the mechanical reason most enterprise pilots return nothing: not bad models, unusable outputs.

So two properties are needed, and they are constantly confused.

Calibration

When it says 0.9, is it right 90% of the time?

Resolution

Does the number vary with whether it is actually right?

A model that says 0.87 on every item and is right 87% of the time is perfectly calibrated and completely useless. There is no threshold that separates anything. Report calibration alone and you would call it excellent.

Read the baseline carefully.

The gazetteer holds the same postal directory these items were generated from. That is realistic, since India Post publishes it and any deployment would have it, but it means this is a lookup measured against models given no reference data at all. It is not lookup against retrieval.

Which makes the honest claim the stronger one: a prompt-only model is the wrong tool for a lookup. That is an argument about architecture, not about model quality.

Then it caught me, eight times.

A bench that only reports what worked is a brochure. This one is unit-tested against its own failure modes, and the tests kept finding mine. Three surfaced only when the simulated providers were replaced with real ones.

    Three of the eight all pointed the same way, toward the conclusion the bench was built to argue for. That is what makes the class dangerous. The errors were not random, they flattered the thesis, and each fix left the next one standing.

    Corrected, the finding reversed. The cheapest design contains no model at all, and every composition that adds one ties or costs more.
